Chapter 01

It's All About Components

React is a component-based UI library. Instead of building one monolithic page, you decompose your interface into small, self-contained building blocks called components. Each component owns its markup, styling, and logic — and can be composed together like LEGO pieces to form complex UIs.

Why Components?

  • Reusability — Write once, use everywhere. A Button component works on every page.
  • Separation of Concerns — Each component handles its own rendering and behavior.
  • Composability — Components nest inside other components, forming a tree.
  • Maintainability — Small, focused units are easier to test, debug, and refactor.

Component Tree

React applications form a component tree. The root component (typically App) sits at the top, and every other component is a descendant. Data flows down via props, and events flow up via callbacks.

jsx 
// The simplest React component — a function returning JSX
function App() {
  return (
    <div>
      <h1>My App</h1>
      <Header />
      <MainContent />
      <Footer />
    </div>
  );
}
💡 Best Practice Name components with PascalCase (e.g., Header, not header). This is required for React to distinguish custom components from native HTML elements.
⚠ Common Pitfall A component must return exactly one root element. Wrap siblings in a <div> or a <>…</> fragment.

Chapter 02

JSX & React Components

JSX (JavaScript XML) is a syntax extension that lets you write HTML-like markup inside JavaScript. It is not a string template — JSX compiles to React.createElement() calls under the hood, producing real JavaScript objects.

JSX vs. HTML — Key Differences

  • class → className (reserved keyword in JS)
  • for → htmlFor
  • Self-closing tags must close: <img />, <br />
  • Inline styles use camelCase: backgroundColor not background-color
  • Event handlers use camelCase: onClick not onclick
jsx 
// JSX is compiled to React.createElement calls
// What you write:
const element = <h1 className="title">Hello</h1>;

// What React compiles it to:
const element = React.createElement(
  'h1',
  { className: 'title' },
  'Hello'
);

Expressions in JSX

Use curly braces {} to embed any JavaScript expression — variables, function calls, ternaries, or arithmetic.

jsx 
const user = { name: 'Alice', age: 28 };

function Profile() {
  return (
    <div>
      <p>Name: {user.name}</p>
      <p>Age: {user.age}</p>
      <p>Next year: {user.age + 1}</p>
      <p>Status: {user.age >= 18 ? 'Adult' : 'Minor'}</p>
    </div>
  );
}
🔥 Common Pitfall You cannot use if/else or for loops directly inside {}. Only expressions are allowed. Use ternary operators or move logic above the return.

Chapter 03

Creating & Using a First Custom Component

Creating a custom component in React is as simple as writing a JavaScript function that returns JSX. This function becomes a reusable tag you can use anywhere in your application.

Step-by-Step

  1. Define a function with a PascalCase name.
  2. Return JSX from that function.
  3. Use the component as a tag: <MyComponent />
jsx 
// Step 1: Define the component
function CustomButton() {
  return (
    <button className="btn">Click Me</button>
  );
}

// Step 2: Use it inside another component
function App() {
  return (
    <div>
      <h1>Welcome</h1>
      <CustomButton />
      <CustomButton />
    </div>
  );
}

Arrow Function Syntax

jsx 
// Arrow function form (equivalent)
const CustomButton = () => {
  return <button className="btn">Click Me</button>;
};

// Implicit return (for simple components)
const Logo = () => <img src="logo.png" alt="Logo" />;
📚 Note React treats components starting with a lowercase letter as native HTML tags. Always start custom component names with an uppercase letter.

Chapter 04

Dynamic Values in JSX

JSX is not a static template — it's JavaScript. You can inject dynamic values anywhere using {} curly braces. This is what makes React UIs truly reactive: when values change, the UI updates automatically.

Where Can You Use Dynamic Values?

  • Between tags: <h1>{title}</h1>
  • In attributes: <img src={imageUrl} />
  • In styles: style={{ color: textColor }}
  • In expressions: {count + 1}, {items.length}
jsx 
function Product() {
  const title = 'React Course';
  const price = 49.99;
  const discount = 0.2;
  const finalPrice = price * (1 - discount);

  return (
    <div>
      <h2>{title}</h2>
      <p>Original: ${{price}}</p>
      <p>Final: ${{finalPrice.toFixed(2)}}</p>
      <p>Savings: {(discount * 100)}%</p>
    </div>
  );
}
⚠ Common Pitfall Objects are not valid as React children. {object} will throw an error. Access specific properties: {user.name}, not {user}.
💡 Best Practice Derive computed values above the return statement for cleaner JSX. Avoid complex expressions inline: {a + b * c} is fine, but longer formulas should use a named variable.
Fig 4.1 — Injecting dynamic values into JSX with curly braces
Chapter 05

Dynamic Attributes & Image Loading

Attributes in JSX can also receive dynamic values. This is essential for image sources, dynamic CSS classes, ARIA labels, and any prop that varies at runtime.

Dynamic Image Sources

When referencing local images stored in your project's src/ folder, you must import them so the bundler (Vite/Webpack) processes and includes them in the output.

jsx 
// Importing a local image asset
import reactImg from './assets/react-core-concepts.png';

function Hero() {
  const altText = 'React Core Concepts';
  return <img src={reactImg} alt={altText} />;
}

Dynamic classNames

jsx 
function NavItem({ label, isActive }) {
  return (
    <li className={isActive ? 'nav-active' : 'nav-item'}>
      {label}
    </li>
  );
}
📚 Image Loading in Vite Vite handles asset imports automatically. The import returns the final URL path after hashing. For images in public/, use a direct string path: src="/logo.png".
⚠ Common Pitfall Never use src={'./image.png'} with a relative string path — the bundler won't process it. Either import the file or put it in public/.

Chapter 06

Component Reusability & Props

Props (properties) are the mechanism for passing data from parent to child. They make components configurable and reusable — a single Card component can render different content depending on the props it receives.

Declaring & Using Props

jsx 
// Reusable component accepting props
function UserCard({ name, role, avatar }) {
  return (
    <div className="user-card">
      <img src={avatar} alt={name} />
      <h3>{name}</h3>
      <p>{role}</p>
    </div>
  );
}

// Using it with different data
function App() {
  return (
    <div>
      <UserCard
        name="Alice"
        role="Engineer"
        avatar="/alice.jpg"
      />
      <UserCard
        name="Bob"
        role="Designer"
        avatar="/bob.jpg"
      />
    </div>
  );
}

Default Props & Destructuring

jsx 
// Default values via destructuring
function Button({ label = 'Click', variant = 'primary' }) {
  return <button className={`btn btn-${variant}`}>{label}</button>;
}
💡 Best Practice Destructure props in the function signature — it's cleaner, documents the component's API, and enables default values.
🔥 Important Props are read-only. A child component must never modify props received from its parent. If you need mutable data, use state (covered in Chapter 12).
Fig 6.1 — Props enable component reusability across your application

Exporting & Importing

jsx 
// Header.jsx — default export
export default function Header() {

  return <Header />;
}
💡 Best Practice Use named exports for utilities and default exports for components. One component per file. Co-locate related CSS and tests with the component.

Chapter 08

The children Prop

children is a special built-in prop that React automatically passes to every component. It represents whatever you place between the opening and closing tags of a component — making it the primary mechanism for composition.

Why children?

  • Creates wrapper / layout components (cards, modals, sections)
  • Makes components flexible — they don't need to know what content they'll contain
  • Follows the composition pattern instead of prop drilling
jsx 
// A generic Card wrapper using children
function Card({ children }) {
  return (
    <div className="card">
      {children}
    </div>
  );
}

// Using it with different inner content
<Card>
  <h2>Title</h2>
  <p>Description text</p>
</Card>

<Card>
  <img src="hero.jpg" alt="Hero" />
</Card>

Combining children with other props

jsx 
function Panel({ title, children }) {
  return (
    <section className="panel">
      <h2>{title}</h2>
      {children}
    </section>
  );
}

// Usage
<Panel title="Settings">
  <SettingsForm />
</Panel>
💡 Best Practice Prefer children over passing JSX as a named prop (e.g., content={<div/>}). It's more idiomatic and easier to read.
Fig 8.1 — The children prop enables flexible composition patterns
Chapter 09

Reacting to Events

React uses synthetic events — cross-browser wrappers around native DOM events. You attach event handlers via camelCase props like onClick, onChange, onSubmit, etc.

Basic Event Handling

jsx 
function Counter() {
  function handleClick() {
    console.log('Button clicked!');
  }

  return <button onClick={handleClick}>Click</button>;
}

Accessing the Event Object

jsx 
function Form() {
  function handleChange(event) {
    console.log(event.target.value); // current input value
  }

  return <input onChange={handleChange} />;
}

Common Events

  • onClick — button/link clicks
  • onChange — input/textarea value changes
  • onSubmit — form submission
  • onMouseEnter / onMouseLeave — hover effects
  • onKeyDown / onKeyUp — keyboard input
🔥 Common Pitfall Do NOT call the handler immediately: onClick={handleClick()} ❌. This executes the function on render. Pass the reference: onClick={handleClick} ✅.
Fig 9.1 — React synthetic events and event handling patterns
Chapter 10

Passing Functions as Props

Functions are first-class citizens in JavaScript, which means you can pass them as props just like any other value. This pattern enables child-to-parent communication — the child calls the function, and the parent handles it.

jsx 
// Parent defines the handler
function App() {
  function handleTabChange(selectedTab) {
    console.log('Tab changed to:', selectedTab);
  }

  return <TabButton onSelect={handleTabChange} />;
}

// Child receives and calls the function
function TabButton({ onSelect }) {
  return (
    <button onClick={() => onSelect('details')}>
      Details
    </button>
  );
}
📚 How It Works The parent defines the function and passes it down via a prop. The child invokes the function at the right time (e.g., on click). This allows the child to communicate events upward without knowing the implementation.
💡 Best Practice Name function props descriptively: onSelect, onDelete, onToggle. This follows the convention and makes the component's API self-documenting.
Fig 10.1 — Passing functions as prop values for child-to-parent communication
Chapter 11

Adding Custom Parameters to Handlers

Often you need to pass extra data to an event handler beyond just the event object. There are several patterns for this, each with different tradeoffs.

Pattern 1: Arrow Function Wrapper

jsx 
function ProductList() {
  function handleSelect(id) {
    console.log('Selected:', id);
  }

  return (
    <ul>
      <li onClick={() => handleSelect(1)}>Product A</li>
      <li onClick={() => handleSelect(2)}>Product B</li>
    </ul>
  );
}

Pattern 2: data-* Attributes

jsx 
function handleClick(event) {
  const id = event.target.dataset.id;
  console.log('Selected:', id);
}

<button data-id="42" onClick={handleClick}>Select</button>

Pattern 3: via Props (Preferred for Custom Components)

jsx 
<TabButton
  label="Details"
  onSelect={() => handleSelect('details')}
/>
💡 Best Practice For custom components, pass the handler already bound with its parameter from the parent. For native elements, use arrow wrappers or data-* attributes.

Chapter 12

Managing State with useState

useState is the most fundamental React Hook. It lets you add state — data that changes over time and triggers a re-render when updated — to functional components.

Syntax

jsx 
import { useState } from 'react';

function Counter() {
  // [currentValue, setterFunction] = useState(initialValue)
  const [count, setCount] = useState(0);

  function increment() {
    setCount(count + 1);
  }

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={increment}>+1</button>
    </div>
  );
}

State with Objects

jsx 
const [user, setUser] = useState({ name: 'Alice', age: 25 });

// Update: spread existing, then override
setUser({ ...user, age: 26 });

Functional Updates

jsx 
// When new state depends on previous state,
// use the functional update form to avoid stale closures:
setCount((prevCount) => prevCount + 1);
🔥 Common Pitfall State updates are asynchronous — you can't read the new value immediately after setState. Also, React merges state updates and may batch them. Use functional updates when the next value depends on the current one.
⚠ Object State Gotcha Unlike this.setState in class components, useState replaces the entire state value — it does NOT merge. Always spread the old object: {...old, key: newVal}.
Fig 12.1 — useState hook and state management fundamentals
Chapter 13

Deriving & Outputting Data Based on State

Not every piece of data needs its own state. When a value can be computed from existing state, derive it instead of storing it separately. This eliminates sync bugs and reduces complexity.

Bad: Redundant State

jsx 
// ❌ Don't store derived values in state
const [items, setItems] = useState(['A', 'B', 'C']);
const [itemCount, setItemCount] = useState(3); // redundant!

Good: Derive from State

jsx 
// ✅ Derive the count — always in sync
const [items, setItems] = useState(['A', 'B', 'C']);
const itemCount = items.length; // derived!

// More examples of derived data
const [price, setPrice] = useState(100);
const [quantity, setQuantity] = useState(2);
const total = price * quantity; // derived

const [todos, setTodos] = useState([...]);
const completedCount = todos.filter(t => t.done).length;
💡 Best Practice Ask yourself: "Can this value be computed from existing state?" If yes, derive it. Only use useState for values that change independently or come from user input / async data.
📚 Performance Note For expensive computations, wrap them in useMemo. But for simple derivations like .length or arithmetic, direct computation is fine — React is fast enough.
Fig 13.1 — Deriving values from state instead of creating redundant state
Chapter 14

Rendering Content Conditionally

React doesn't have built-in directives like v-if or ngIf. Instead, you use plain JavaScript — ternary operators, logical AND, and early returns — to conditionally render elements.

Method 1: Ternary Operator

jsx 
function Alert({ message }) {
  return (
    {message ? <p className="alert">{message}</p> : null}
  );
}

Method 2: Logical AND (&&)

jsx 
// Renders the element only if condition is truthy
function Profile({ user }) {
  return (
    <div>
      <h2>{user.name}</h2>
      {user.isAdmin && <badge>Admin</badge>}
      {user.email && <p>{user.email}</p>}
    </div>
  );
}

Method 3: Early Return

jsx 
function UserDetails({ user }) {
  if (!user) return <p>Loading…</p>;

  return <div>…</div>;
}

Method 4: Variable Assignment

jsx 
function TabContent({ activeTab }) {
  let content = <p>Please select a tab.</p>;

  if (activeTab === 'details') {
    content = <DetailsPanel />;
  } else if (activeTab === 'settings') {
    content = <SettingsPanel />;
  }

  return <div>{content}</div>;
}
⚠ Common Pitfall with && {0 && <div/>} renders 0 on screen because 0 is falsy but a valid React node. Use a ternary or explicit boolean: {count > 0 && <div/>}.
Fig 14.1 — Multiple patterns for conditional rendering in React

CSS Styling & Dynamic Styling

React supports multiple styling approaches. Choosing the right one depends on project size, team preference, and whether you need dynamic styles.

1. Inline Styles

jsx 
// Inline styles use camelCase properties and an object
<div style={{
  backgroundColor: '#1a1a2e',
  padding: '20px',
  borderRadius: '8px'
}}>
  Content
</div>

2. CSS Classes (Traditional)

jsx 
// Import a CSS file and use className
import './Button.css';

function Button({ variant }) {
  return <button className={`btn btn-${variant}`}>Click</button>;
}

3. Dynamic className

jsx 
function Tab({ isActive, children }) {
  return (
    <button className={isActive ? 'tab active' : 'tab'}>
      {children}
    </button>
  );
}

4. CSS Modules

jsx 
// Button.module.css — scoped by default
import styles from './Button.module.css';

function Button() {
  return <button className={styles.primary}>Click</button>;
}
💡 Best Practice Use CSS classes for static styling, inline styles for truly dynamic values (like positioning from state), and CSS Modules or scoped solutions for avoiding class name collisions.

Outputting Lists Dynamically

To render a list of items, use JavaScript's .map() method to transform an array of data into an array of JSX elements. This is the standard React pattern for dynamic lists.

Basic List Rendering

jsx 
function ConceptList() {
  const concepts = [
    { id: 'cmp', title: 'Components', desc: 'UI building blocks' },
    { id: 'jsx', title: 'JSX', desc: 'Declarative syntax' },
    { id: 'props', title: 'Props', desc: 'Data passing' },
  ];

  return (
    <ul>
      {concepts.map((concept) => (
        <li key={concept.id}>
          <h3>{concept.title}</h3>
          <p>{concept.desc}</p>
        </li>
      ))}
    </ul>
  );
}

Extracting List Items as Components

jsx 
// Reusable list item component
function ConceptItem({ title, description }) {
  return (
    <li>
      <h3>{title}</h3>
      <p>{description}</p>
    </li>
  );
}

// Parent maps data to components
{concepts.map((c) => (
  <ConceptItem
    key={c.id}
    title={c.title}
    description={c.desc}
  />
))}
🔥 Critical: The key Prop Every list item must have a unique key prop. Keys help React identify which items changed, added, or removed — enabling efficient re-renders. Never use the array index as key if the list can be reordered or items can be inserted/removed.
⚠ Common Pitfall Using index as key can cause bugs with controlled inputs, animations, and reordering. Use a stable unique identifier from your data (e.g., item.id).

Mini-Project: Interactive Tab Viewer

Let's combine everything we've learned — components, props, state, events, conditional rendering, and dynamic styling — into a single working mini-project: an Interactive Tab Viewer.

Project Overview

The app displays three tabs (Components, JSX, Props). Clicking a tab reveals its description. The active tab is visually highlighted. All logic lives in the parent; child components are pure and reusable.

Project Structure

text 
src/
├── components/
│   ├── TabButton.jsx
│   └── TabContent.jsx
├── App.jsx
└── App.css

TabButton.jsx

jsx 
export default function TabButton({ children, isSelected, onSelect }) {
  return (
    <li>
      <button
        className={isSelected ? 'active' : undefined}
        onClick={onSelect}
      >
        {children}
      </button>
    </li>
  );
}

App.jsx

jsx 
import { useState } from 'react';
import TabButton from './components/TabButton';

const TAB_DATA = {
  components: 'Components are the building blocks…',
  jsx: 'JSX is a syntax extension for JS…',
  props: 'Props let you pass data from parent to child…',
};

export default function App() {
  const [selectedTopic, setSelectedTopic] = useState('components');

  function handleSelect(topic) {
    setSelectedTopic(topic);
  }

  return (
    <div id="app">
      <h1>React Essentials</h1>
      <menu>
        <TabButton
          isSelected={selectedTopic === 'components'}
          onSelect={() => handleSelect('components')}
        >Components</TabButton>
        <TabButton
          isSelected={selectedTopic === 'jsx'}
          onSelect={() => handleSelect('jsx')}
        >JSX</TabButton>
        <TabButton
          isSelected={selectedTopic === 'props'}
          onSelect={() => handleSelect('props')}
        >Props</TabButton>
      </menu>
      <div id="tab-content">
        {TAB_DATA[selectedTopic]}
      </div>
    </div>
  );
}

Chapter 18

Interview Q&A

Prepare for React interviews with these commonly asked questions covering the essentials covered in this guide.

Q1: What is React and why use it?
React is a declarative, component-based JavaScript library for building user interfaces. Key advantages: component reusability, virtual DOM for efficient updates, unidirectional data flow for predictability, and a vast ecosystem.
Q2: What is JSX? How is it different from HTML?
JSX is a syntax extension that lets you write HTML-like markup in JavaScript. Key differences: className instead of class, htmlFor instead of for, self-closing tags are required, inline styles use camelCase objects, and expressions are embedded with {}.
Q3: What is the difference between props and state?
Props are read-only data passed from parent to child — they cannot be modified by the child. State is mutable data owned by the component itself, managed with useState (or this.setState in class components). State changes trigger re-renders.
Q4: Why must React component names start with an uppercase letter?
React treats lowercase tags as native HTML elements and PascalCase tags as custom components. If you name a component with a lowercase letter, React won't recognize it as a component and will try to render it as an HTML element, resulting in an error.
Q5: What is the virtual DOM?
The virtual DOM is a lightweight JavaScript representation of the real DOM. React renders components to the virtual DOM, then diffs it against the previous version. Only the changed parts are updated in the real DOM (reconciliation), making updates efficient.
Q6: What is the key prop and why is it important?
The key prop is a unique identifier for list items. It helps React's reconciliation algorithm identify which items changed, were added, or removed. Without proper keys, React may incorrectly reuse DOM nodes, causing bugs with animations, controlled inputs, and component state.
Q7: How do you handle events in React?
React uses synthetic events — cross-browser wrappers around native events. Attach handlers with camelCase props like onClick. Pass the function reference, not a call: onClick={handler}, not onClick={handler()}. Access the event object as the first parameter of the handler.
Q8: What is the children prop?
children is a special prop that React automatically passes to every component. It represents the content placed between the component's opening and closing tags. It's the primary composition mechanism for creating wrapper/layout components.
Q9: Why shouldn't you store derived values in state?
Storing derived values in state creates redundancy and potential sync bugs — if the source state changes but the derived state isn't updated, they'll be out of sync. Instead, compute derived values directly from existing state: const total = price * quantity;. This guarantees consistency.
Q10: What are the different ways to conditionally render in React?
Four main patterns: (1) Ternary — {condition ? <A/> : <B/>}; (2) Logical AND — {condition && <A/>}; (3) Early return — if (!data) return <Loading/>; (4) Variable assignment — set a variable and render it. Choose based on complexity and readability.
Q11: What happens if you call setState with the same value?
If the new state value is the same as the current value (determined by Object.is comparison), React bails out of the re-render for optimization. This is important for performance — unnecessary renders are skipped automatically.
Q12: Can you pass a function as a prop? Why would you?
Yes — functions are first-class in JavaScript. Passing functions as props enables child-to-parent communication. The child invokes the function at the right time (e.g., on click), and the parent handles it. This is the standard pattern for lifting state up and keeping child components reusable.
Q13: What is the difference between controlled and uncontrolled components?
Controlled components have their value driven by React state — value={state} + onChange. Uncontrolled components manage their own internal DOM state, accessed via refs. Controlled components are preferred for predictable behavior and validation.
Q14: Why is index as a React key an anti-pattern?
Using the array index as a key is problematic when the list can be reordered, filtered, or have items inserted/removed. React uses keys to match previous and new items. With index keys, item identity is tied to position, causing React to incorrectly associate state with wrong items. Use a stable unique ID from your data instead.
Q15: How does React's one-directional data flow work?
Data flows down via props (parent → child). Events flow up via callback functions passed as props. This unidirectional flow makes data ownership clear, debugging easier, and prevents the cascading updates that can occur in two-way binding systems.
Q16: What are React Hooks?
Hooks are functions that let you "hook into" React features from functional components. useState adds state, useEffect adds side effects, useContext accesses context, useRef creates refs, etc. Hooks must be called at the top level of a component — not inside loops, conditions, or nested functions.
Q17: What is the difference between default and named exports?
A module can have one default export (imported with any name: import MyComponent from './file') and multiple named exports (imported with exact name: import { helper } from './file'). Convention: default export for the main component, named exports for utilities.
Q18: How do you update object/array state without mutation?
Since React state must be updated immutably: for objects, use spread: setState({...old, key: newVal}). For arrays, use spread or array methods that return new arrays: setState([...old, newItem]), setState(old.filter(...)), setState(old.map(...)). Never mutate directly: state.push() ❌.
Q19: What is reconciliation in React?
Reconciliation is the process by which React compares the new virtual DOM tree with the previous one and determines the minimum set of changes needed to update the real DOM. It uses a diffing algorithm with key assumptions: elements of different types produce different trees, and the developer can hint at element stability with key props.
Q20: What are the rules of Hooks?
Two rules: (1) Only call Hooks at the top level — never inside loops, conditions, or nested functions. This ensures hooks are called in the same order every render. (2) Only call Hooks from React function components or custom Hooks — not from regular JavaScript functions. Use eslint-plugin-react-hooks to enforce these rules.
